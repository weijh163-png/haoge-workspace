# 税务师考试学习页整合设计

## 目标

在不改变“浩哥工作台”现有栏目、业务功能和整体结构的前提下，完善“税务师考试”入口：展示用户报考的三个科目，并将现有《税法（Ⅰ）》学习网站完整迁入工作台，使其不再依赖外部网站即可使用。

## 已确认范围

- 税务师考试包含三个科目：税法一、税法二、涉税服务实务。
- 本次完整整合税法一。
- 税法二、涉税服务实务仅显示“待完善”，不创建学习内容。
- 点击税法一后，在工作台当前页面内部切换到完整学习页面，不打开新浏览器标签页。
- 保持原工作区结构和已有业务数据不变。

## 现状

- 线上工作台为单页静态应用，“税务师考试”目前只打开考试倒计时弹窗。
- 税务师区域目前只显示“税务师三科”和考试日期，没有科目明细。
- 税法一学习网站是独立单页应用，包含今日学习、十二章知识树、章节练习、错题本、四阶段冲刺计划及说明页面。
- 税法一学习进度使用浏览器 `localStorage` 中的 `tax1state` 保存。
- 当前本地仓库没有工作台源文件，因此实施阶段需要先从公开 GitHub Pages 对应仓库取得源文件，再进行增量修改。

## 方案

采用“本地子页面 + 工作台内部容器”的隔离方案。

### 工作台入口

保留首页现有“税务师考试”按钮和考试弹窗。将弹窗中的税务师区域扩展为三个清晰可辨的科目项：

1. 税法一：显示“进入学习”，可点击。
2. 税法二：显示“待完善”，不可进入学习页。
3. 涉税服务实务：显示“待完善”，不可进入学习页。

中级经济师倒计时及弹窗内其他既有信息保持不变。

### 税法一内部学习页

将外部税法一网站的完整页面复制到工作台仓库的独立目录 `tax-law-one/`。工作台增加一个学习页容器；点击“税法一”后，关闭考试弹窗、隐藏工作台主界面，并在当前页面显示该本地学习页。

学习页容器提供明确的“返回工作台”操作。返回后恢复原工作台界面及用户进入学习页之前的滚动位置，不触发整页跳转或新标签页。

独立子页面用于隔离两套页面的 CSS、导航代码和全局变量，避免工作台已有 `.card` 等通用类名与税法一页面冲突。

### 数据流与持久化

- 税法一 HTML、CSS、JavaScript、题目、章节数据和计划数据全部保存在工作台仓库内。
- 工作台加载同源的 `tax-law-one/index.html`，不依赖原外部网页运行。
- 税法一继续使用独立键 `tax1state` 保存答题数、正确率、错题、任务状态和最近学习日期。
- 工作台原有本地数据键保持不变，税法一不得读写或覆盖工作台业务数据。
- 原网址只作为迁移来源记录，不作为运行时依赖。

## 交互与异常处理

- 税法二和涉税服务实务使用非交互状态样式并标注“待完善”，避免让用户误以为可以进入。
- 税法一页面加载期间显示简短加载状态。
- 如果本地学习页加载失败，容器显示失败提示和“返回工作台”按钮；不自动跳转到外部网站。
- 浏览器不支持或禁用本地存储时，学习页仍可浏览和答题，但提示进度可能无法在刷新后保留。
- 桌面端与移动端均提供固定可见的返回入口，且不会遮挡学习页导航。

## 文件边界

- 工作台主入口文件：只增加科目列表、学习页容器、进入/返回控制和必要样式。
- `tax-law-one/index.html`：保存税法一学习应用的完整本地副本，并进行最小的嵌入适配。
- 不拆分或重构工作台其他模块，不调整现有收入核算、流程、报表或备份功能。

## 验收标准

1. 工作台原有页面、导航、数据和功能正常。
2. 点击“税务师考试”后能看到税法一、税法二、涉税服务实务三个科目。
3. 税法一可以点击，另外两科明确显示“待完善”。
4. 点击税法一后在当前工作台页面内显示完整学习台，不打开新标签页。
5. 今日学习、知识树、章节练习、错题本、冲刺计划和大纲说明均可使用。
6. 答题和任务进度在刷新后仍能恢复，且不影响工作台原有数据。
7. 点击“返回工作台”能恢复进入前的工作台界面。
8. 税法一运行时不再请求原 GitHub Pages 页面；原网站失效不影响本地副本。
9. 桌面和手机宽度下均可进入、操作和返回。

## 实施验证

- 对比修改前后工作台的主要导航与业务模块。
- 检查考试弹窗三科状态及键盘可访问性。
- 完成一次税法一答题，制造一条错题并刷新，确认状态恢复。
- 返回工作台后检查滚动位置和原有状态。
- 检查浏览器控制台错误及网络请求，确认没有对原税法一网站的运行时依赖。
- 在桌面宽度和移动宽度分别执行一次完整进入与返回流程。
